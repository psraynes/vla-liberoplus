Completed job 2568735, exact OFT sample from OpenVLA-OFT commit e4287e94541f459edc4feabc4e181f537cd569a8; git blob 8863226be214ba60f8be5b3674d272024df93439. Batch one, 50 warmups and 300 timed fresh adapter calls; original checkpoint dtype, precision and flow steps. Resizing 224->256 bilinear occurs before timing; frozen adapter rotation/preprocessing/model/first-action postprocessing/host transfer are inside the end-to-end boundary. Reset is outside timing. A thin counter verifies 350 fresh model calls rather than queued-action timing. Model-only is a separate CUDA-event sample_actions pass, not LLM-only.

Per-action cost is median query time divided by ten executed actions, not all 50 generated actions and not measured closed-loop latency. The adapter returns one action and queues nine; extra preprocessing in later queued calls is outside this amortized fresh-query metric. Peak primary memory is PyTorch allocated including resident model during the timed pass after warmup, reported in GiB despite the legacy `*_gb` field. Reserved memory is secondary; neither is total process/device peak. TurboVLA's older memory window also included warmup/component timing, a small residual protocol distinction.

Raw numeric samples and hashes are included in benchmark.json; account path roots and internal DNS suffix are redacted. Original/public hashes are in source_exports/PROVENANCE.json. Only base and pre-repair v3 were profiled; repaired-model speed is unmeasured. Matching speed inputs does not remove success-evaluation simulator differences.
